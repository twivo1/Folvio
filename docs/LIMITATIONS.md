# Known limitations and roadmap

Folvio 0.10 is the first public release. It is tested automatically on Windows and Linux, but it is young software:
keep backups of important documents (Folvio does so by default when it overwrites a file).

## Platforms
* Windows 10 (1809+) and 11, x64. The installer is not code-signed yet (SmartScreen warning on first run).
* Linux x86_64 with glibc 2.39+ (Linux Mint 22.x, Ubuntu 24.04+, Fedora 40+). Tested in clean Linux Mint 22.1/22.2,
  Ubuntu 24.04/26.04 and Fedora 43 containers with an X server; Wayland was checked through WSLg only, not on a
  full desktop installation. Linux Mint 21.x / Ubuntu 22.04 (glibc 2.35) are not supported.
* Drag & drop is tested through Qt's real event path, but the operating system's own drag loop (OLE on Windows,
  X11/Wayland on Linux) cannot be driven by automated tests.
* Microsoft Word integration (better PDF → DOCX) exists only on Windows. On Linux LibreOffice rebuilds the PDF layout
  with positioned text boxes.
* FFmpeg, LibreOffice and the Tesseract engine are not bundled (licences of the available builds would require
  shipping many source packages): Windows installs them through `winget` on request, Linux through the distribution.
* No ARM builds, no macOS build, no Flatpak/Snap yet.

## Native PDF editing (Auto Change)
* Changed lines are written with the document's own embedded font whenever every character already exists in
  that (subset) font - same look and metrics. Characters that are not in the subset require an installed
  TrueType font matched to the original (warned in the UI); its ToUnicode map is generated by Folvio so copy and
  search work in other applications.
* A paragraph may only grow into free space. If the new text needs more room and the space is occupied by other
  text or graphics, the edit is refused (nothing changes, the typed text stays in the editor) and Reflow edit is
  offered. Folvio never moves other paragraphs.
* Lines containing characters that the PDF does not map to Unicode (shown as �) cannot be rewritten; other lines
  of the same paragraph can.
* A line whose text changes is written in one style; mixed bold/italic *inside* that line is unified (warned).
* Text in form XObjects, rotated text and Type 3 fonts are shown but not editable in place.
* Paragraph detection is heuristic; complex multi-column or table layouts may group lines differently than a
  human would. Lines added beyond the original paragraph can overlap content below (warned).
* Adding text grows only within the page; there is no automatic re-pagination (use reflow editing for that).
* Encrypted PDFs: PDFium may write the saved file without encryption; Folvio detects this and warns before saving.
* Digitally signed PDFs are saved incrementally; the signature will show the document as modified.

## Reflow editing
* Round trip goes through HTML/ODT: tracked changes, comments, fields, text boxes, headers/footers and section
  layouts of DOCX files are not preserved by the editor (conversions DOCX→PDF keep them – tested).
* PDF reflow quality depends on Microsoft Word (best) or LibreOffice (approximate).

## OCR
* Recognition produces an invisible, searchable text layer; scanned pages stay images. Editing *visible* text of a
  scan (whiteout + retype) is not implemented yet.
* OCR results always need review; uncertain words (< 70 % confidence) are highlighted.
* **Handwriting recognition is experimental** (optional download, PP-OCRv6 small): on real English handwriting
  photos (GNHK) about 57 % of the words are recognised exactly (CER 33.5 %); Polish handwriting has not been
  measured on real samples. Formulas and drawings are not understood. Details: `docs/HANDWRITING_OCR.md`.
* Recognize Text with *Printed text* often returns nothing on grid or ruled paper (Tesseract); use *Auto* or
  *Handwriting*, or type the text.
* Windows: the handwriting module needs the Microsoft Visual C++ runtime (present on practically all Windows 11
  systems; otherwise `winget install Microsoft.VCRedist.2015+.x64`).

## Conversions
* `PPTX→PNG` exports via PDF (one image per slide). XLSX→CSV exports the first sheet.
* AVIF encoding and HEIC decoding depend on the FFmpeg build (verified with the gyan.dev full build).
* Word-based conversions cannot be force-killed if Word itself hangs (it is a COM server outside the job object).

## Combine
* *Auto* proportions come from a camera model. If the page is only tilted forwards/backwards (one pair of edges
  parallel in the photo) the focal length cannot be measured and a typical phone lens is assumed — the ratio can
  then be off by a few percent; choose A4/Letter/Custom when the paper size is known.
* Page detection needs some contrast between the page and the background (white paper on a white desk is
  often not found); the corners can always be placed by hand.
* Images pasted from a browser as remote links are not downloaded (only bitmaps and local files are imported).
* HEIC/AVIF import requires FFmpeg with the corresponding decoder.
* Pen pressure is exported as segments of different widths (not a single variable-width outline); the eraser
  removes shapes and text boxes as a whole.
* Text annotations use the fonts installed in Windows; a font without a needed glyph falls back to Arial.
* Auto Change image editor: unsaved changes to an image are not recovered after a crash (Combine has session
  recovery; the image editor keeps nothing outside the exported files). Closing asks before discarding changes.
* Images pasted into a PDF are stored as a bitmap (PNG pixels); very large screenshots make the PDF larger
  than a JPEG would. Cropping hides parts without deleting them until the PDF is saved; only the visible part is
  written to the file.

## Roadmap
1. Visual whiteout + retype for scanned pages using OCR boxes.
2. Reuse of embedded fonts when all needed glyphs are present.
3. Per-run style preservation in edited lines.
4. Visual diff report export (Compare view already renders pixel differences).
5. Code signing of the installer, MSIX package, Linux/macOS builds (architecture is portable; Windows specifics
   are isolated in `ProcessRunner`, `SafeFileWriter`, `DependencyManager`).
