# Testing

`build/release/tests/folvio_tests.exe` (GoogleTest). Tests generate their own fixtures at run time (PDFs with
`QPdfWriter`, media with FFmpeg `lavfi`, DOCX/encrypted PDFs with Python's standard library + `pypdf`) and run
real engines. Tests that need a missing engine are reported as *skipped*, never as passed.

Last full run (2026-11-18, Windows 11, all engines present): **60 tests, 60 passed, 0 skipped**.

The release script (`packaging/build_release.ps1`) runs the suite and additionally smoke-tests the deployed
application with a minimal `PATH` (no Qt SDK) before building the installer.

UI checks: `Folvio.exe --screenshot out.png [--page N] [--theme light|dark] [--demo-edit] [file]` renders the
window to an image and exits (used to review layouts in both themes).

## Diagnostics tool

`build/release/pdfdiag.exe` (developer only, not installed):

* `dump file.pdf` – text objects, lines and paragraph blocks
* `baseline file.pdf` – rebuild with a no-op edit and verify
* `sweep file.pdf outdir` – edit every paragraph once; checks validator, character multiset and pixels outside the edited line; failing outputs are written to `outdir`
* `edit file.pdf "<text in block>" "<old>" "<new>" out.pdf` – one specific edit
* `compare a.pdf b.pdf out.png [y0 y1]` – render the same region of two files

It prints structure and statistics only and never writes next to the input file. Real documents used for
diagnosis are copied to a temporary folder first and are not added to the repository.
